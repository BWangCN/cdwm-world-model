# Drop rollout WM — design decision + progress

Living record for the drop **trajectory (rollout) world model**: the discussion that motivated it, the decision, the plan, and (below, updated as it runs) the training + model-vs-ground-truth results.

## The question (2026-07-24)
Reviewing the pushed drop docs, two design questions came up:
1. Should the drop WM model the **free-fall / impact dynamics** (a trajectory), not just the endpoint?
2. The demo GIFs are **MuJoCo ground-truth re-simulations, not model output** — is that misleading, and why would we need them?

## Discussion + Codex verdict
- The current drop Gate B WM is **endpoint-only**: `GateBDiT` is H=1, it denoises the *final resting SE(3)*, which we bin into stable-pose basins for a calibrated `P(basin)`. The demos are MuJoCo re-sims that sweep the hidden CoM to show the *mechanism* (CoM → basin), not diffusion samples.
- **Codex (session pressure-test): endpoint-only is defensible for the current paper.** The multimodality is concentrated in the settle *outcome*; the free-fall is near-deterministic. Modeling the trajectory adds narrative symmetry with grasp (H=32) / slip (K=10), not new evidence. It insisted on: keep endpoint eval; add a terminal-state **limitation**; **relabel the demos** as physics counterfactuals (not model output); and include at least one **model-output** visualization so the section is not only simulator clips.
- Done + pushed (`cdwm-world-model`, branch `restructure-common-grasp-drop`): demos relabeled "physics counterfactuals, NOT model output"; a Scope & limitation section added (drop = terminal-state distributional WM; grasp/slip are trajectory WMs sharing the encoder).

## Decision (author's call)
**Build the diffusion rollout for drop now** (pulled ahead of "future work"). Rationale: it unifies the "imagine the future" story across grasp/slip/drop, produces **model-generated** settling rollouts (the honest replacement for the GT-resim demos), and makes multimodality visible as **diverging** rollouts (same release, different hidden CoM → the model tumbles into different basins). Then update this doc and the repo demos with **model rollout alongside ground truth**.

## Plan
1. **Trajectory data** (`gen_rollout.py`, icing1 CPU): re-simulate each gateb episode from `com_sim` (deterministic), record the object orientation at K evenly-spaced steps from release to settle → `<obj>_roll_s0.npz` `traj_quat (N,K,4)`. Reuses `drop_sweep` (hull + explicit-inertial CoM).
2. **Rollout dataset + model**: `GateBDiT` with **H=K** (the DiT head already supports H; grasp uses H=32), target = K-step orientation relative to release (6D, like the endpoint but a trajectory). Same shared encoder + latent arms (no_latent / grounded).
3. **Train** (GPU sbatch), same 3-arm design; eval = trajectory distribution (energy score / per-step drift) + endpoint basin recovery.
4. **Render model vs GT**: sample the K-step rollout, render the object tumbling to rest; place next to the GT re-sim. Diverging samples under the same release = the model imagining multiple settling futures.

## Convex-hull scope (2026-07-25)
Prompted by "the spinosaurus and bull don't look reasonable — how does the model have such low error?" The renders exposed a real modeling boundary (not a bug), worked through with Codex.

**Cause (not a bug).** Both the sim and the WM operate on the point-cloud **convex hull**. Mesh-cloud alignment is fine (nn-dist median 0.046). The issue is that the hull ≠ the real shape for concave objects: the bull's hull has 3 stable resting modes vs the mesh's 8. The model's low diffusion loss is on the *hull* resting task, which for concave objects does not match how the real mesh settles, so a detailed mesh drawn at a hull pose looks wrong even when the predicted basin is right.

**Why the hull at all (why we can't just use meshes).** Of 89 Gate B objects, **60 are point-cloud-only** (no source mesh exists); the hull is the only geometry buildable for them. A rigid sim collides convex geometry natively. And the hull is matched to the WM input cloud, so sim and WM share one representation (no geometry confound).

**Codex verdict (two rounds).** (1) Hull is defensible + scope it honestly, not a fatal flaw; convex decomposition (CoACD) is the right direction for concave fidelity but future work, and only end-to-end geometry-consistent (WM cloud re-sampled from the decomposed mesh). (2) On the plan: don't hard-code the convex/concave threshold (read it from the ratio distribution); add a contact-facing proxy beyond volume ratio; keep one concave counterexample; stratify the headline numbers by fidelity if they support the claim.

**Did (path a, no retraining).** Data-derived audit `concavity_audit.py` (two proxies: global convexity ratio, natural gap ~0.74; stable-pose loss, median 1, max 5 for the bull; the two correlate only -0.11 so volume alone does not flag the problem objects). Transfer gain stratified by hull fidelity is **positive in every stratum** (faithful +0.204, unfaithful +0.320, cloud-only +0.165) — the effect is not a hull artifact. Demo redone with convex-ish objects; scope-boundary figure added (`render_scope.py`: bull real mesh vs the legless hull blob). Overview doc updated with a "Geometry: the convex-hull scope" section.

**Update — the "60 have no mesh" framing was too strong (measured + reworded, pushed e42374d).** The 60 are standard GSO/YCB ids whose meshes are PUBLIC; our local objects/ just holds the 171 GRASP objects. So the hull is a scoped CHOICE, not a data impossibility. Also measured: the 29 local meshes track the observed cloud to ~1.6% (median cloud->mesh); 32/89 objects are legged/handled by type but only 4/29 measurable show severe resting-mode collapse; clouds are FULL-surface (hull_vol/mesh_vol 0.90-1.01). Codex: reviewer risk MODERATE not fatal; run the 29-object CoACD comparison if the paper can absorb it.

**Path b, SCOPED comparison — DONE (`hull_vs_coacd.py`, icing1 array job 1105798, 29/29, user chose "run it now"). ★ SUPERSEDES the global concavity-audit proxy for boundary-regime claims.** Confound-free 3-arm design: identical release + identical explicit-inertial hidden CoM, ONLY the collision geometry differs (single hull vs CoACD multi-hull), + a 1.5deg-release-wobble sensitivity FLOOR to isolate ordinary near-boundary noise from a geometry effect. "Same resting pose" = yaw-invariant orientation match (`DS.basin_diff<30deg`), not lossy stable-pose binning (binning was the bug in the first design pass — see below). Design iteration required THREE fixes before the numbers were trustworthy: (1) settle criterion moved from "75 consecutive steps below a velocity threshold" to ORIENTATION-stability (`settle_robust`) — the decomposed surface micro-rolls right at the angular threshold, so CoACD settled 3/20 vs hull 20/20 with the naive criterion; (2) mesh centered at its convex-hull-vertex mean (not all-vertex mean) to match `DS.hull`'s convention; (3) metric switched from mesh-stable-pose assignment to direct `basin_diff` — assigning to mesh poses was lossy and gave nonsensical delta=0 sanity results (55-78% agreement at zero CoM offset, should be ~100%); the direct metric fixed it (bull 39/40 at delta=0).
**RESULT (29/29, n~250/obj):** ALL: agree 0.76 | 1.5deg floor 0.95 | **geom_gap +0.19** | median rest-diff 10.4deg. convex-ish-by-OLD-proxy (25): floor 0.96, **gap +0.16**. concave (4): floor 0.93, gap +0.38. **The old global proxy under-states boundary sensitivity**: 2 of 3 first-pass demo objects it called "hull-faithful" (the Marc_Anthony bottles) have LARGE gaps (+0.31, +0.13); `051_large_clamp`, excluded as "concave" by the old proxy, has one of the SMALLEST gaps (+0.05) — same lesson as the Gate-A.5 "transition-rate != CoM-sensitivity" finding, now recurring as "global-shape-proxy != boundary-regime hull sensitivity." **CORE CLAIM SURVIVES**: re-stratified the Gate B reldisjoint result (28/29-object overlap, dist>point + oracle>diff/CoM-causal) by geom_gap tertiles instead of the old proxy: dist>point gain stable across low/mid/high-gap (+0.473/+0.520/+0.425), oracle>diff (CoM causal) if anything LARGEST in high-gap (+0.033 vs +0.023 low); corr(geom_gap, per-obj gain)=-0.27 (weak). So the distributional/hidden-latent mechanism does not concentrate in or depend on hull-sensitive objects — only the PREDICTED RESTING POSE fidelity is at risk for a geometry-sensitive minority.
**Codex sign-off on the finding:** update the Q1 verdict to "genuine quantitative limitation on Gate B's predicted-pose fidelity, not just concave-demo cosmetics"; re-pick demo objects by the corrected metric (done: skillet_lid/large_clamp/conditioner, the 3 lowest-gap held-out mesh objects — transparently, not cherry-picked-to-look-good, just sorted by the same validated metric); old "median 1 mode lost" doc claim kept but explicitly scoped as answering a different, less relevant question; don't launch a bigger campaign today since the stratification showed the main result does NOT depend on high-gap objects. Doc + demo + code shipped (`bb6c7e1`).

## Trajectory-supervision experiment (2026-07-25, user Q: "predict intermediate frames — better performance?")
User proposed supervising intermediate frames (a couple during the fall, a couple after impact, the settled state). Analysis (self → Codex converged): (1) **zero-signal reduction** — the corpus uses zero-velocity kinematic release, so during-fall orientation is CONSTANT and height is closed-form ballistics; during-fall frames are trivially predictable and carry no causal information → the proposal reduces to supervising the IMPACT→SETTLE transient + endpoint. (2) **No tail fix expected from a deterministic trajectory head** — same conditioning information as the endpoint head; open-loop prediction cannot resolve WHICH-WAY multimodality (that is Gate B's distributional job); plausible small gain from transient supervision as an inductive bias, worth measuring. (3) Codex design refinements: anchor frames from CONTACT ONSET (detected as first orientation deviation >0.5°, fallback ballistic estimate) → settle, per-sample duration fractions, equal chordal loss over anchors (endpoint weighting only as a later ablation), K=8 = implementation convention (half gateb's K=16), readout = endpoint median + the ≥15° tail stratum vs the H=1 baseline, same object-disjoint split. Corpus-trajectory DIFFUSION rollout retrain deferred (would change supervision AND predictive family at once).
**Build:** `precompute_droptraj.py` (K=8 anchors, rows aligned to drop_index order, release-quat cross-check stored; smoke: k0 med 4 ≈ ballistic impact, last anchor == rest frame) → `DropTrajDS` (targets precomputed in __init__, hot path unchanged from the efficiency-reviewed baseline) → `DropTrajNet` (same encoder, rot head 6K) → `train_droptraj.py` (mirrors train_drop; equal chordal over K; dumps test_pred.npz with geo0 for tail strata). Jobs: precompute 1105846 (icing1, 2m43s, 160,200 eps) → train 1105847 (V100, 49 min).
**★ RESULT (seed 0, paired per-episode test dumps, object-bootstrap CIs over the 12 held-out objects):**
- **ENDPOINT: transient supervision SIGNIFICANTLY improves the bulk** — per-object median gain **+0.28° [+0.08, +0.79] SIG**, better on **10/12** held-out objects; overall median **2.38° → 2.01°** (no-motion 7.45°). The user's hypothesis CONFIRMED for the bulk (my "little headroom" prior was too pessimistic).
- **TAIL (≥15° tips, n=313): NOT fixed** — gain +0.59° [−0.86, +2.42] ns; both arms still tie no-motion (16.31/16.51 vs 16.05) → the which-way multimodality is a REPRESENTATION problem (Gate B's distributional job), not a supervision-density problem. Both mechanism predictions held.
- Alignment sanity: the two dumps share objects + geo0 to float noise (max 0.002°) → episodes genuinely paired.
- **Codex verdict on the result:** ship with fixed-protocol wording; single seed acceptable for RECORDING (paired object-bootstrap over held-out objects is the right unit) but run a second seed before making traj_k8 canonical; do NOT replace full_release as reference yet — report traj_k8 as the preferred-candidate variant.
